# Wiki Documentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the component documentation out of `README.md` into one GitHub Wiki page per component, add accurate contributor documentation, and turn the README into a short overview that links every component.

**Architecture:** The Wiki is its own git repo (`https://github.com/NoMercy-Entertainment/nomercy-ffmpeg.wiki.git`, branch `master`), cloned next to the main repo. Pages are Markdown files named after the page. A checker script (outside both repos) proves links, sidebar coverage, README coverage and the internal-terms rule. Main-repo changes (README, CONTRIBUTING, `actions.md` removal, npm README link, mapping table) are one commit on dev.

**Tech Stack:** GitHub Wiki Markdown (GFM; wiki links `[Text](Page-Name)`), Python 3 for the checker.

**Spec:** `docs/superpowers/specs/2026-11-15-wiki-docs-design.md`

## Global Constraints

- One page per component; never several components on one page (owner). A long page may get sub-pages.
- The Wiki describes the latest release on master: v1.0.47 = `7fca656` (owner). "since vX.Y" markers stay where behaviour changed; internals of past releases go.
- English. Short sentences, one idea per sentence, tables for options (owner is dyslexic; outside readers skim).
- No internal infrastructure: no Forgejo, no `phillippepelzer`, no host/runner machine names, no tokens. Say "the project's self-hosted runners".
- Contributor route: issue first, PR only after the proposal is agreed; then fork → PR into `dev`; fork PRs get no CI, maintainers build and test before merging (owner).
- Licence text is copied unchanged; nothing new is claimed about licensing.
- Every claim is checked against scripts, workflows, or the v1.0.47 release/Verify RC run; what cannot be shown is dropped or marked "not verified".
- README ≤ 200 lines; every NoMercy-only component on its own line with a Wiki link; bundled libraries as one grouped line to `Codecs-and-Libraries`.
- Nothing is pushed (Wiki or dev) without the owner's say-so. Local commits only.

## Review Focus

1. A reader following any link (sidebar, README, page-to-page) lands on an existing page — checker `links` pass.
2. A component in today's README that has no page or no README line — checker `coverage` pass against the component list in Task 1.
3. A stale claim copied over (CI diagram with a "Linux x86_64 hardware" job, "every master build publishes an RC", "JPEG XL/HAP/APV ship after v1.0.45", a GPG-signed manifest) — each listed in the mapping table's "dropped as stale" column with its evidence.
4. Internal infrastructure leaking onto a public page — checker `internal` pass.
5. An option name, default or range that differs from the v1.0.47 binary — every option table is generated from or checked against `ffmpeg -h filter=<name>` of the v1.0.47 linux-x86_64 binary (Task 3/4).
