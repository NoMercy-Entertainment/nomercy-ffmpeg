# JPEG XL implementation and verification

Design: [static JPEG XL](../specs/2026-11-03-jpeg-xl-design.md).
Issue: <https://github.com/NoMercy-Entertainment/nomercy-ffmpeg/issues/109>.

1. Check upstream 0.12.0 CMake and pkg-config definitions against the issue's sketch.
2. Add the numbered build script and static-link checks.
3. Add shared generated-fixture tests to Bash/PowerShell manual and smoke suites.
4. Run cross-compilation probes sequentially, inspect foreign headers, and test
   the full native Linux package.
5. Review the diff, document verification limits, and commit locally.

## Verification results

Completed locally on 2026-11-04.

The cross-compilation probes use the platform Dockerfile's compiler, sysroot, CMake
arguments and hardening flags, followed by the production `62-libjxl.sh` and a
small FFmpeg build enabling both JPEG XL wrappers. Unrelated Java/Rust codecs,
packaging and signing are outside those probes. A full production Linux build
is checked separately. Local logs and probe files are in `output/jpeg-xl/`.

| Target | Build/link | Runtime |
| --- | --- | --- |
| linux-x86_64 | Focused static FFmpeg and full production package passed | All three JPEG XL checks passed; full smoke passed; codec suite 28 passed, 15 skipped, 0 failed |
| windows-x86_64 | Focused static FFmpeg passed; system DLL imports only | All three checks passed on AVX2, PowerShell 5.1/7 and Git Bash |
| linux-aarch64 | Focused static FFmpeg passed | All three checks passed under QEMU Cortex-A53 (not physical hardware) |
| windows-aarch64 | Focused FFmpeg passed; ARM64 PE header and system DLL imports verified | No Windows ARM64 host available |
| freebsd-x86_64 | Focused static FFmpeg passed; x86_64/FreeBSD ELF header verified | No FreeBSD host available |
| darwin-x86_64 | Focused FFmpeg passed; x86_64 Mach-O header verified; only libSystem/libc++ imports | No macOS host available |
| darwin-arm64 | Focused FFmpeg passed; ARM64 Mach-O header verified; only libSystem/libc++ imports | No macOS host available |

- Smoke gate regression harness: 12 passed, 0 failed. Includes missing still and
  animated encoders, altered alpha despite successful commands, and a crash at
  default encoder settings. Existing version/dispatcher/cross-exec cases pass.
- Both lossless checks and the default-settings check pass with Bash 3.2 under
  `set -eu`; the helper avoids that shell's empty-array/nounset pitfall.
- Injected configure, build and install failures each abort without enabling
  libjxl (3/3). The previous NoMercy binaries fail the new codec checks.
- A flag-boundary probe confirms the Win64 assembler workaround reaches both
  CMake compiler-flag arguments intact, including the existing flags with spaces.
- All seven focused binaries carry the JPEG XL configure flag and animation
  wrapper. ELF targets are static; Windows imports only system DLLs; Darwin
  imports only libSystem and libc++. No JPEG XL/Brotli/Highway runtime library
  is imported.
- Full Linux smoke and codec suite both exit 0. All three JPEG XL checks run.
  The 15 skipped codec-suite cases are 4 GPU/platform checks and 11 model/asset
  checks, with reasons in `output/jpeg-xl/full-linux/report.json`. The ggml
  startup guarantee still runs; the production linker check confirms all four
  CPU variants survived the link. No model-based inference parity is claimed.
- ShellCheck passed for the build script, Bash helper and smoke harness
  (`-e SC2086` for the established space-separated CMake toolchain arguments).
  PowerShell parsing passed; `git diff --cached --check` and the staged review
  passed. No source outside this feature and its test fixtures was changed.

Foreign binary headers and successful cross-linking do not establish runtime
correctness on those operating systems. No real-hardware release checklist is
ticked by these probes, and no release is created for this feature alone.
