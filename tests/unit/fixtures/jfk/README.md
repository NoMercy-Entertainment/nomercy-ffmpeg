# JFK port fixture for `lyricsalign` (#126)

The prototype's numbers on whisper.cpp's `samples/jfk.wav` (public domain, 11 s, 16 kHz mono, sha256
`59dfb9a4acb36fe2a2affc14bacbee2920ff435cb13cc314a08c13f66ba7860e`), copied from
`eval/fixtures/jfk/` of the lyrics-creator plugin repository, so the C port can be checked without the
copyrighted reference set. The clip itself is not in git; `tests/lib/lyricsalign-assets.sh` fetches it.

- `jfk-logprobs-f16.npy`: `[550 x 392]` log-softmax emissions of `facebook/wav2vec2-xlsr-53-espeak-cv-ft`,
  f32 on CPU (transformers 5.22.1, torch 2.11.0), one 22 s window (20 s core + 1 s context each side,
  zero-padded, per-window zero-mean unit-variance input, context frames dropped), stored as float16.
- `jfk-alignment.json`: the espeak-ng 1.52.0 `en-us` phones of the JFK sentence, their vocabulary ids,
  the Viterbi's first frame and posterior per phone (star weight 0.3, line blank penalty 0.05), per-word
  start and score, the line's spike start, end and onset-walked-back start.
- `jfk-ipa.txt`: the raw `espeak-ng -q --ipa --sep=_ -v en-us` output for the sentence (the string the
  parser is tested on).
- `jfk_fixture.h`: the JSON as C arrays, generated by `make_fixture_h.py`; regenerate after changing the
  JSON, never edit by hand.

Gates the issue sets on these: emissions with the same argmax on at least 99 % of frames and a mean
absolute difference under 0.05 nats; the C Viterbi reproducing every phone frame exactly; the filter's
word starts within 40 ms of `words[].start`.

The JSON and the `.npy` are regenerated in the plugin repository with
`python -I eval/fixtures/jfk/make.py jfk.wav eval/fixtures/jfk` (needs the torch model); copy both here
and run `python -I tests/unit/fixtures/jfk/make_fixture_h.py`.
